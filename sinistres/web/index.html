Comment c'est fait

Mettre le PDF entier dans un chatbot marche sur un contrat et s'écroule ensuite : pas de citation fiable, pas de comparaison, un coût qui grandit avec chaque question. Ici, chaque contrat est préparé une fois et rangé dans une base ; chaque sinistre devient ensuite une requête et deux appels à un modèle.

How it's built

Putting the whole PDF in a chatbot works on one contract and falls apart after that: no reliable citations, no comparison, a cost that grows with every question. Here each contract is prepared once into a database; each claim then becomes a query and two model calls.

1. Le modèle pointe, il ne réécrit pas

PyMuPDF extrait chaque ligne avec sa page et sa position (lecture en deux colonnes, en-têtes et pieds de page retirés). Le modèle lit une page à la fois et renvoie seulement des numéros de ligne : lesquelles sont des titres, où commence et finit chaque clause. Le texte d'une clause est ensuite recopié du PDF par le code. Une citation affichée est donc toujours le texte du contrat, et une ligne que le modèle aurait oubliée devient une clause à part entière : rien n'est perdu en silence.

1. The model points, it does not rewrite

PyMuPDF extracts every line with its page and position (two-column reading, headers and footers removed). The model reads one page at a time and returns only line numbers: which lines are headings, where each clause starts and ends. The clause text is then copied from the PDF by the code. A citation on screen is therefore always the contract's own text, and a line the model skipped becomes a clause of its own: nothing is silently lost.

2. Un vocabulaire commun, une base pour des centaines de contrats

Chaque assureur nomme et range ses chapitres à sa façon. Chaque clause reçoit donc un type (garantie, exclusion, condition, définition, limite…) et des périls pris dans une liste fixe (vol, dégâts des eaux, incendie, jardin, objets de valeur et vélos…). Un contrat est une ligne, une clause est une ligne : ajouter cent contrats ajoute des lignes, pas de la complexité. « Quels contrats excluent les vols dans des locaux non clos ? » devient une requête.

2. A shared vocabulary, one database for hundreds of contracts

Every insurer names and orders its chapters differently. Each clause therefore gets a kind (guarantee, exclusion, condition, definition, limit…) and perils from a fixed list (theft, water damage, fire, garden, valuables and bikes…). A contract is a row, a clause is a row: a hundred more contracts add rows, not complexity. “Which contracts exclude theft from unlocked rooms?” becomes a query.

select c.insurer, cl.page_start, cl.text
from clauses cl
join contracts c on c.id = cl.contract_id
join clause_perils p on p.clause_id = cl.id
where p.peril = 'vol_vandalisme' and cl.kind = 'exclusion'
  and cl.text like '%non clos%';

3. La recherche est du SQL

Un premier appel transforme le récit en faits : périls, biens, lieu, et les mots qu'un contrat utiliserait (« cycle », « parties communes », « effraction »). Trois requêtes réunissent ensuite les clauses utiles, puis on ajoute les définitions des termes qui apparaissent. Pas de base vectorielle : la structure du contrat est déjà dans les colonnes.

3. Retrieval is SQL

A first call turns the story into facts: perils, property, place, and the words a contract would use (“cycle”, “parties communes”, “effraction”). Three queries then gather the useful clauses, and the definitions of the terms that appear are added. No vector store: the contract's structure is already in the columns.

4. Le modèle constate, le code décide

Le modèle ne donne pas de verdict. Il qualifie les faits, cite les clauses, puis répond à trois questions : une garantie s'applique-t-elle, une exclusion, une condition non remplie ? Le code vérifie chaque citation mot pour mot, exige qu'un doute s'appuie sur des mots du récit (sinon l'assuré est présumé avoir respecté ses obligations), applique une règle explicite, et rétrograde en « indéterminé » tout verdict qui ne repose pas sur une clause vérifiée. Un « je ne sais pas » sourcé vaut mieux qu'une réponse assurée sans justification.

4. The model finds, the code decides

The model does not give a verdict. It classifies the facts, cites clauses, then answers three questions: does a guarantee apply, an exclusion, an unmet condition? The code checks every citation word for word, requires a doubt to rest on words of the claim (otherwise the policyholder is presumed to have met their obligations), applies an explicit rule, and downgrades to “undetermined” any verdict that does not rest on a verified clause. A sourced “I don't know” beats a confident unsupported answer.

Limites connues

  • Les conditions générales ne suffisent pas : options, plafonds et franchises sont dans les Conditions Particulières. Le système le dit plutôt que de le supposer.
  • Le modèle est petit (ministral-14b, niveau gratuit de l'API Mistral) : découpage parfois trop large, quelques étiquettes et chemins de section faux, et un raisonnement qui se trompe encore. Les contrôles limitent l'effet de ces erreurs sans l'annuler ; l'onglet Évaluation le mesure.
  • Tableaux complexes et PDF scannés non traités.

Known limits

  • General conditions are not the whole contract: options, ceilings and deductibles live in the policy schedule. The system says so instead of assuming.
  • The model is small (ministral-14b, Mistral API free tier): segmentation sometimes too coarse, some wrong labels and section paths, and reasoning that still makes mistakes. The checks limit the effect of these errors without cancelling it; the Evaluation tab measures it.
  • Complex tables and scanned PDFs are not handled.
